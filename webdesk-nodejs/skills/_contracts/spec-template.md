### 8.2 Dashboard (if UI in scope)

**Modules AND Settings sections/fields are SOW-derived** — analyze the SOW and include only the modules, KPIs, health items, and Settings sections/fields it defines. Never hard-code a fixed module list or Store/API/ERP Settings fields (Store Name, Store URL, API Key, Access Token, Client Secret, API Path, …) unless the SOW names them. A store-connection or ERP-connection Settings section appears **only because a given SOW names a store/ERP**, not as a default. See `_spine/designer-agent/knowledge/01-dashboard-standards.md` (the SOW-driven dashboard standard).

The **only fixed system contracts** (same on every build regardless of SOW):

- **Auth:** JWT (access + refresh, rotation, server-side revocation list), show/hide password fields.
- **Tenancy:** [per-client | per-client + master]. Every query tenant-scoped; only the master role has cross-tenant scope.
- **RBAC:** per-module permission matrix — **View/Edit/Delete is the minimum** every module carries, extended per module with Create/Approve/Export/Import/Run/Configure/Manage All where that module needs them. Matrix rows (modules) come only from the SOW.
- **Settings → Timezone:** the operational clock (stored UTC, displayed local; changing it reschedules crons).
